# Agent Note: 拒绝不再延续已观测范围的会话产物追加

Status: implemented

[English](2026-09-18-session-artifact-concurrent-writer-refusal.md) | 中文

## Problem

两个共用同一 `~/.dsh` 主目录的 `dsh` 进程加载了同一会话，并向其 `.jsonl.zstd` 产物各自追加事件。其中一个持有正在等待长时间工具调用的活动轮次；另一个恢复该会话，在已存储前缀中发现一个未闭合的轮次，并用活动轮次即将使用的序号提交了合成的崩溃恢复收尾事件。工具返回后，活动轮次在同样的序号上追加了真实结果，因此已提交区域中这些序号各出现两次，所有读取方都拒绝了整份日志。同一主目录下的第二个会话出现了完全相同的碰撞，且不涉及崩溃恢复：一次恢复写入了它的 `session/end-seed` 边界，而活动写入方内存中的事件计数仍落后于产物。[事故复盘 0005](../../../../docs/postmortem/0005-concurrent-process-writers-duplicated-committed-sequences.md) 记录了这两次事件、恢复过程，以及仍未落实的防护措施。

排他此前是按进程划分的。协调器的所有者映射只会拒绝它能观察到的所有者，`isPreparedSourceCurrent` 只比较准备期间读取到的修订版本，而 JSONL 追加路径只回滚自身那部分写入。基准早于另一写入方批次的写入方会追加格式良好、却没有任何读取方能接受的字节，唯一的信号是之后整份会话被拒绝。

## Decision

JSONL 后端记录每个产物的**已观测范围**——持久字节长度与已提交事件计数——并拒绝不再延续该范围的持久化变更，在任何字节改变之前抛出 `SessionPersistenceConflictError`（由 `dsh-session-persistence` 导出）。该拒绝会指出会话、两个字节长度及其后果：接下来的事件会重复已经提交的序号。

每次完整前缀读取（`readPrefix`）和每次持久写入（`materialize`、`appendLines`、`repair`）都会记录该范围。读取记录的是*已提交*事件计数，而不是返回的事件计数：撕裂末帧中被恢复的事件要等修复重新追加后才持久，因此计数必须与修复所延续的序号基准一致。`repair` 在截断后重新记录截断后的范围，正是这一点让被恢复的事件与收尾事件得以追加。

`appendLines` 在任一字段不匹配时拒绝，`repair` 在字节长度不匹配时拒绝。之所以在字节长度之外还检查事件计数，是因为脱离式读取同样会观测该产物：`readFrom`（折叠后缀的投影缓存）会重新读取同一文件，而重新观测到另一写入方的日志绝不能重新武装过期写入方的基准。`materialize` 会记录它刚刚发布的那个范围，因此延迟创建会话的首次追加从自身字节开始。

组装后的组合由 `examples/headless-agent/tests/session-write-conflict.snapshot.ts` 固定：一个 fixture 通过公开 agent 服务恢复种子会话，随后用同一根目录上的第二个后端实例推进该产物，运行会以该拒绝文本失败。

## Alternatives considered

**在 `PersistenceBackend.loadStored` 上增加读取意图参数。** 逐调用传入 `'adopt'` 或 `'read'` 可以阻止脱离式读取重新播种基准，而这一区分正是事件计数字段存在的原因。之所以否决，是因为计数检查在不需要扩大协调器与后端之间约定的情况下堵住了同一个漏洞：所有现有的 `loadStored` 调用点，包括第三方后端与测试替身，都将不得不声明一个只有单一后端在意的意图。

**只比较字节长度。** 否决：外部追加之后 `readFrom` 重新播种基准，会让下一次过期追加比较相等，从而静默恢复本次改动所消除的损坏。

**每会话的持久租约或锁文件。** 这是针对刻意共享同一会话的进程的修复方案。暂缓：它需要承担过期判定、接管、拒绝文案与拆卸语义，而当前没有消费者在进程间共享同一会话。该守护先把意外情况变为显式拒绝。

**按 DSH 主目录拒绝第二个实例。** 覆盖了报告中的部署形态，但会阻断合法的多实例使用（源码构建与已安装构建并存），也不覆盖 Web 服务旁的 CLI 或 ACP 写入方。见[事故复盘的替代方案](../../../../docs/postmortem/0005-concurrent-process-writers-duplicated-committed-sequences.md)。

**让读取方容忍重复区域。** 否决：重复内容已是提交数据，因此既不能把它当作事实提供，也不能在该处截断，截断会丢弃其后所有真实事件。

## Consequences

过期写入方现在会在下一次追加或截断修复时显式失败，而不是损坏日志，它未触碰的日志也保持可读。该检查缩小了竞态，但无法让追加成为原子操作：在同一瞬间打开同一产物的写入方仍可能在该写入方的尺寸检查与实际写入之间完成追加，因此刻意的跨进程共享仍需要日志之外的存活信号，协调器自身也不增加排他。SQLite 未实现等价守护，因此该类问题在该后端仍未缓解。

包内覆盖固定了追加拒绝、脱离式读取重新观测到外部产物后的拒绝，以及本会丢弃另一写入方已提交轮次的被拒截断修复；移除该守护时这三项都会失败。组装场景通过真实 Loader 固定了面向产品的拒绝文本。
